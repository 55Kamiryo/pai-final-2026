# カメラ異常への停止・復旧処理の実証

提出対象は、手元カメラの一時的な画像欠損に対する停止・復旧処理である。
モデル・基本タスクを再利用し、今回の追加機能とその役割を動画・PDFで示す。

## 処理

`camera_recovery.py`が、画像の欠落・形状不正・非有限値・全黒画像を毎ステップ監視する。
異常中は腕6成分の移動指令を0にし、直前のグリッパー指令を維持する。
正常画像が3フレーム続いたら古い動作列を破棄し、現在の観測からAIが再予測する。
実機安全機構ではなく、フリーズ画像などすべての故障を検知するものではない。

## 提出物に収録した実測

保存初期状態index 0・seed 42、1タスク・各条件1回。
異常条件ではstep 20〜59（1秒以上3秒未満）に手元画像を全黒へ置換した。

| 条件 | 観測結果 |
| --- | --- |
| 画像正常（参考） | 94ステップ（4.70秒）で達成 |
| 画像欠損・対策なし | 280ステップ（14.00秒）で未達成 |
| 画像欠損・停止復旧あり | step 20で停止、62で再開、134（6.70秒）で達成 |

停止中42ステップの保存ログで、腕6成分の指令がすべて0、グリッパー指令が停止前と
同じであることを確認した。物理的な完全停止や実機での安全性の証明ではない。
1配置・各条件1回であり、一般的な成功率改善や統計的な優位性は未確認。

## シミュレーションの再実行

ルートREADMEに従い依存関係と公開アセットを準備して、プロジェクト直下から実行する。
学習・W&Bへの送信は行わない。

```bash
uv run python experiments/probe_camera_recovery.py \
  --capture-inputs --include-normal --output-root outputs/camera-submission
uv run python build_camera_submission.py \
  --input outputs/camera-submission --account YOUR_ACCOUNT
```

再実行時の成否・時間が変わった場合、動画・PDF本文・概要欄も読み込んだ結果に合わせて生成する。
比較条件・停止中の行動ログが記載の説明と矛盾する場合は、生成を中止する。

## 収録済み結果からの再生成

```bash
uv run python build_camera_submission.py --account YOUR_ACCOUNT
```

必要な元映像・入力画素・行動ログは、同梱の`results/camera-recovery/`にある。
モデルの再実行なしで再生成できる。フォントなどの要件はルートREADMEを参照する。

## 手元画像の小窓だけを付けた比較

```bash
uv run python experiments/build_camera_preview.py \
  --input results/camera-recovery
```

`wrist_inputs.npz`に、全黒への置換後・行動実行前の実際の入力画像を保存した。
画像の向きはモデル前処理と同じ180度回転。小窓のstep iと全体映像のframe iを対応させる。
AIが画像を参照するのは動作列の再予測時のみで、停止中は監視処理が復旧を確認する。
完了後は最終入力の静止表示を明記する。

小窓付き約15秒の動画は確認用。課題提出には、ルートREADME記載の説明を含む約1分16秒の動画を使う。
